## 1. 项目目标和交付边界

实现或改进一个通用 LLM 数据分析助手：接收 `task.json` 和该题 `context/`，自主发现文件、理解业务规则、调用工具、关联计算，最终生成 `task_N/prediction.csv`。

| 事项 | 必须满足的要求 | 课件依据 |
| --- | --- | --- |
| 范围 | 完整数据有 410 题输入，课程只运行公开参考答案对应的固定 60 题；不能直接取前 60 个题号 | 第 1、8 张 |
| 系统 | 同一套通用 Agent 批量运行，包含模型接入、工具系统、Harness、状态与停止控制、错误恢复 | 第 1、5 张 |
| 输入能力 | 按题处理 CSV、JSON、SQLite、Markdown/PDF、视频；读取存在的 `knowledge.md`，遵守单位与业务口径 | 第 2–4 张 |
| 答案隔离 | `gold.csv` 仅在预测后的独立评测中使用，不进入解题提示词或工具输入 | 第 2 张 |
| 结果 | 每题保存可读 CSV，以及执行日志、耗时和失败原因；单题失败后批量任务仍能继续 | 第 5、7 张 |
| 课程指标 | 指定列匹配评分器，λ＝0.1，固定 60 题均分乘 100，缺失预测按 0 分计入 | 第 7、8 张；指南第 8 节 |
| 改进目标 | 在同一题集与评分设置下尝试超过 75.6387/100；先建立自己的可复现基线 | 第 8 张 |
| 报告 | 逐题及平均得分，满分/部分分/零分题数，耗时，案例与错误分析，优化对照和个人贡献 | 第 7 张 |

基线由 `ecnu-max` 运行 32 题、`ecnu-plus` 运行 28 题得到，但课件没有给出完整配置或具体分配。因此本项目起步固定一种账户可用模型，记录其配置，不能预设可精确复现参考分数。

必交六项：完整源码、环境与依赖配置、预测 CSV、复现文档、实验评测记录、期末报告。允许使用现成模型 API，无须自行训练大模型。分组、截止日期、评分权重尚未在课件中说明，以教师通知为准，不阻塞环境准备。

## 4. 分阶段搭建与验收

### 阶段 A：系统工具和目录

参照指南 3.2，复用当前 Ubuntu，补齐系统工具并安装 uv。系统包安装需当前账户具备 sudo 权限，实际权限尚未验证。

```bash
sudo apt-get update
sudo apt-get install -y git curl unzip ca-certificates build-essential ffmpeg
curl -LsSf https://astral.sh/uv/install.sh -o /tmp/kdd-uv-install.sh
sh /tmp/kdd-uv-install.sh
source "$HOME/.local/bin/env"
mkdir -p "$KDD_ROOT/downloads" "$KDD_ROOT/data" "$KDD_ROOT/runs" "$KDD_ROOT/docs"
uv --version
ffmpeg -version
```

验收：uv、Git、unzip、系统 FFmpeg 可执行；项目目录可写；记录系统、Python、CPU/内存和磁盘状态。此阶段不要求 Docker 服务或 CUDA。

### 阶段 B：获取参考代码与锁定 Python 环境

沿用指南核对过的固定版本，不直接跟随 main 自动升级：

```bash
git clone https://github.com/zhezh/kddcup2026_champion.git "$KDD_ROOT/champion"
git -C "$KDD_ROOT/champion" checkout bdc874fc4260e3565ae0dce041728fdf5b376709
git clone https://github.com/HKUSTDial/DataSpace.git "$KDD_ROOT/DataSpace"
git -C "$KDD_ROOT/DataSpace" checkout 6491caa4c70cc06cacb6103ba73cefb00746abfe
cd "$KDD_ROOT/champion"
uv sync --frozen --python /usr/bin/python3.12
uv run --frozen python --version
uv pip check
```

当前已有 Python 3.12，因此优先复用系统解释器建立 `.venv`。只有解释器缺失或锁定依赖不兼容时，才使用指南的 `uv python install 3.12` 路线，并记录最终补丁版本。

运行指南 3.4 的依赖导入检查，覆盖 pandas、DuckDB、Polars、PyArrow、SQLite、PyMuPDF、PyAV、faster-whisper 和 pydantic-ai。即使先测表格题，也保留仓库锁定的完整依赖；可以推迟 ASR 权重下载，不随意删减依赖。

验收：两个提交号准确，`uv sync --frozen` 和 `uv pip check` 成功，导入检查通过，记录 `uv.lock` 的 SHA-256。包源失败时先检查仓库 `uv.toml`、锁文件及网络，不能以全面升级依赖代替定位。

### 阶段 C：数据下载、校验与 60 题输入构建

参照指南第 4 节，全部下载和解压位置改用 `$KDD_ROOT`：

1. 下载完整发布压缩包和对应 `.sha256`，校验通过后解压。
2. 保存公开 `public_reference_tasks.json`，记录获取日期及文件哈希；题单当前为 60 题，第一题是 `task_10`。
3. 核对题单无重复，60 个 ID 与公开 gold 和评测配置 ID 集合一致；这里只核对路径和编号，不读取答案内容。
4. 仅复制每题 `task.json` 与 `context/` 到 `data/input60/`；目录已存在时先核对，禁止静默覆盖。
5. 确认 `input60` 不含 `gold.csv`，统计副本实际磁盘占用；从输入文件清单挑选一题表格/SQL 题用于首次试跑，不根据答案挑题。

验收：压缩包校验成功，60 题输入完整、题号一致，原始数据保留不改。后续 Agent 仅获得当前题输入及必要工作目录，不向其提供完整 benchmark 根目录或答案路径。由于参考工具能执行代码，还需审查工具路径权限；仅把答案放在另一个目录不足以保证隔离。

### 阶段 D：模型接口与工具调用

参照指南第 5 节配置：

```bash
export MODEL_API_URL='https://chat.ecnu.edu.cn/open/api/v1'
export MODEL_NAME='ecnu-plus'
read -r -s -p '输入 ChatECNU API Key: ' MODEL_API_KEY
printf '\n'
export MODEL_API_KEY
unset MODEL_API_URLS DEFAULT_MODEL_API_URLS
export ASR_BACKEND='local'
```

`ecnu-plus` 仅为初始候选，以账户实际可用模型为准。令牌由用户在本机交互式终端输入，不写入计划、Git、日志或版本记录。准备不含密钥的 `.env.example`；若采用 `.env`，显式安排加载方式和忽略规则，不能假定参考入口自动加载。

先运行指南 5.2 的小请求：确认鉴权、响应结构和 `echo` 工具调用。再由单题运行确认工具执行结果可回传、多轮循环可继续。视频验证另需确认图像输入兼容性。

验收：小请求观察到符合预期的 `tool_calls`；记录模型名、基础 URL、测试结果和可获得的用量，不记录令牌。未取得有效令牌时可继续数据与本地预检，但不能宣称模型联调通过。

### 阶段 E：最小真实单题闭环

创建独立实验目录并显式设置：

```bash
cd "$KDD_ROOT/champion"
export RUN_ID="smoke_$(date +%Y%m%d_%H%M%S)"
export RUN_DIR="$KDD_ROOT/runs/$RUN_ID"
export INPUT_DIR="$KDD_ROOT/data/input60"
export OUTPUT_DIR="$RUN_DIR/predictions"
export TEMP_DIR="$RUN_DIR/temp"
mkdir -p "$OUTPUT_DIR" "$TEMP_DIR"
```

对阶段 C 选定的表格/SQL 题使用 `--only-tasks <实际题号> --max-parallel 1`，以指南的 `timeout 30m` 作为首轮调试上限。`task_10` 是指南可用的启动示例，但未检查其输入前，不预设它一定是纯表格题。

验收：模型完成真实工具循环，生成可读 `prediction.csv`，保存执行日志、耗时、失败信息及版本记录。检查 CSV 列、单位、完整性、行内字段关系以及是否误带索引。完成预测后再独立评分；单题分数用于诊断，不作为完整 60 题成绩。

### 阶段 F：多媒体能力补齐

参照指南第 6 节，先下载参考实现需要的 faster-whisper tiny/medium 权重，再运行缓存复制脚本；不要在空缓存下直接运行 `prepare_models.sh`。

验收内容：

- `champion/asr_models/tiny` 与 `medium` 各有 `model.bin`、`config.json`、`tokenizer.json`、`vocabulary.txt`。
- `static-ffmpeg` 的 FFmpeg/FFprobe 均能启动；系统 FFmpeg 成功不能替代此检查。
- `preflight.py` 的 PyAV、static-ffmpeg、Whisper local CPU 检查通过。
- 至少一题公开多媒体任务完成音频转写、所需图像输入与最终 CSV 输出，记录 CPU、内存和耗时。

预检与转写均从 `champion` 工作目录执行，以满足相对权重路径。保持任务并发 1；参考程序内部仍可能并发调用模型。若出现内存不足，先定位峰值，再决定提高 WSL 内存或调整方案，不能以跳过失败任务作为完整验收。

### 阶段 G：基础环境最终验收与批量基线衔接

阶段 A–F 通过后，才进入固定 60 题基线实验。新建实验目录，显式 `--max-parallel 1`，记录任务成功/失败、耗时、token 用量（接口提供时）和预测缺失清单。

预测后运行课程 `run_compare_to_gt.py`，显式传预测路径与 `--gold-path`，核实 `scores.csv` 覆盖准确的 60 题、分数范围为 0–1，并以均分乘 100 与 75.6387 比较。当前 λ 在脚本中是 `LAMBDA_EXTRA = 0.1`，不应添加不存在的 `--lambda` 参数。

课程评分与官方整表评测分别报告：前者用于课程基线比较，后者可补充检查行内关联、精度和行序。不能用两套指标互相替代，也不能因列匹配得分较高而省略业务正确性检查。

基础环境交付物为：可运行的锁定环境、固定版本参考代码、已校验的 60 题输入、无密钥配置模板、接口和多媒体预检记录、单题输出与日志、复现命令及版本记录。完整 60 题成绩属于接下来的基线实验交付，不以“安装成功”替代。

## 5. 执行顺序与当前待办

按 A → B → C → D → E → F → G 推进，每一阶段通过验收再扩大运行范围。无令牌时可独立完成 F 的本地权重和解码预检；依赖、数据及接口准备过程中，持续记录磁盘与内存变化。

| 优先级 | 下一步 | 完成判据 |
| --- | --- | --- |
| P0 | 使用指定项目目录补齐 uv、unzip、FFmpeg，获取固定代码并同步环境 | 导入检查和依赖一致性检查通过 |
| P0 | 下载并验证数据，构建独立 input60 | 校验通过、固定 60 个 ID、无 gold 混入 |
| P0 | 准备用户令牌与可用模型，联调工具调用 | 接口小请求和真实单题闭环通过 |
| P1 | 下载 ASR 权重并完成多媒体预检与单题验证 | 预检通过且资源使用可接受 |
| P1 | 固化环境记录、配置模板、复现命令 | 文档与实际路径、版本、运行结果一致 |
| 后续实验 | 新建实验运行 60 题，独立评分后开展系统改进 | 得到完整可复现基线与错误分析 |
