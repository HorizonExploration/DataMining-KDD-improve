## 1. 项目到底要做什么

实现或改进一个基于大语言模型的自动数据分析助手。输入是自然语言问题及该题的数据目录，系统自行发现数据、调用工具、关联信息并计算，最终输出 `prediction.csv`。

典型问题：统计 2025 年各地区有效订单销售额，并保留销售额达到门槛的地区。系统可能需要从 CSV 读取订单、从 Markdown 提取门店与地区映射、从 `knowledge.md` 理解有效订单定义，最后完成筛选、关联、聚合及排序。

课程的重点是可运行的通用系统和可复现实验，无须自行训练大模型。可以通过 API 调用现成模型。

### 1.1 课程明确要求

| 项目 | 要求与解释 |
| --- | --- |
| 任务范围 | 公开参考答案对应的 60 题；完整数据集有 410 道输入，不要默认运行全部 410 题 |
| 运行方式 | 同一套通用 Agent 批量运行，不能为每题人工编写答案 |
| 输入 | `input/task_N/task.json` 与该题 `context/` |
| 数据形式 | CSV、JSON、SQLite、Markdown、PDF、视频，具体以任务实际内容为准 |
| 输出 | 每题一个 `task_N/prediction.csv`，并保存日志、耗时和失败原因 |
| 答案隔离 | `gold.csv` 只用于预测完成后的评测，不进入解题上下文或工具可读输入 |
| 课程评分 | 课件指定列匹配评分器，λ＝0.1 |
| 参考基线 | 75.6387 / 100；课件说明由 ecnu-max 跑 32 题、ecnu-plus 跑 28 题得到 |
| 优化目标 | 在相同 60 题和评分设置下尝试超过课程参考基线 |
| 实验报告 | 逐题及平均得分、满分/部分分/零分题数、耗时、案例、错误分析、优化对比 |

课件没有给出分组规定、截止日期、评分权重，也没有给出上述 32/28 题的具体模型分配与完整基线配置。这些不能从课件推断。先固定一个模型跑出自己的基线，后续再开展对照实验。

### 1.2 需要实现的系统模块

| 模块 | 工作内容 | 验收表现 |
| --- | --- | --- |
| 模型接入 | 提供问题、数据清单、工具描述和历史反馈，解析工具调用 | 模型可以实际触发工具调用 |
| 主程序 / Harness | 每题独立状态、主循环、停止条件、批量调度、失败恢复 | 一题失败后整批仍可继续 |
| 数据工具 | 文件探索、表格处理、SQL、文档抽取、视频转写和图像分析 | 计算过程能追溯到输入证据 |
| 输出校验 | 检查 CSV 可读性、列及业务含义、重复记录、单位、排序 | 输出完整结果表，保存时不附加 DataFrame 索引 |
| 独立评测 | 生成预测后再读取 gold 和评分器 | 统计固定 60 题，缺失预测也进入分母 |
| 实验管理 | 保存代码、模型配置、日志、用量和耗时 | 同一版本可以复现并比较优化效果 |

推荐流程：读取问题与文件清单 → LLM 选择工具 → 工具执行 → 返回结果或错误 → LLM 继续决策 → 保存 CSV → 独立评分。

## 2. 部署路线与资源准备

### 2.1 推荐 Windows + WSL2 + Ubuntu + uv + Python 3.12

这是部署建议。参考项目使用 Bash、Linux 路径和本地多媒体工具，Dockerfile 也基于 Python 3.12 Linux 镜像。采用 WSL2 可以减少移植工作。先在 WSL 本地跑通，再考虑 Docker 打包；课程课件没有要求必须交 Docker 镜像。

当前工作目录只有课件，没有现成项目代码。已检测到 Windows PATH 中有 Git、Python、WSL 和 Docker 命令，未检测到 uv。命令存在并不代表 Ubuntu 已初始化或 Docker 服务正在运行。

以下硬件为初始规划建议，非比赛或课程最低配置，也非性能承诺：

| 资源 | 建议 |
| --- | --- |
| CPU | 4 核以上，从任务并发 1 开始 |
| 内存 | 16 GB 可先做单题验证，32 GB 更便于视频与多任务实验 |
| 磁盘 | 至少预留约 40–60 GB，覆盖压缩包、约 15 GB 上下文、环境、ASR 权重及实验副本；多轮实验需要更多 |
| GPU | 调用远程 LLM、参考代码使用本地 CPU ASR 时，不以本地 GPU 为前提 |
| 网络与权限 | 能访问 GitHub、Hugging Face、Python 包源和校内模型服务，具备模型令牌与配额 |

大语言模型权重由 API 服务提供，本机只准备数据处理依赖和可选/按需使用的 ASR 权重。参考方案包含额外模型调用与投票，任务并发 1 也不等于每时刻只有一次 API 请求。

### 2.2 建议目录

代码和 Python 环境放在 WSL 的 Linux 文件系统内，例如 `~/kdd2026`。原始 PPTX 保留在 Windows 当前目录。下文所有 Bash 命令均在 Ubuntu 终端运行，只有 WSL 初始化步骤在 PowerShell 运行。


### 4.2 核对题目集合并复制解题输入

下面读取的是独立公开题目清单及路径信息，不读取 gold 的答案内容。使用副本可防止工具误改原始输入，同时避免将答案复制进解题目录。

```bash
cd "$HOME/kdd2026/champion"
uv run --frozen python - <<'PY'
import json
import shutil
from pathlib import Path

root = Path.home() / 'kdd2026/data'
bench = root / 'DataSpace-Benchmark'
manifest = json.loads((root / 'public_reference_tasks.json').read_text(encoding='utf-8'))
ids = manifest['task_ids']
assert manifest['task_count'] == len(ids) == len(set(ids)) == 60
gold_ids = {p.parent.name for p in (bench / 'output').glob('task_*/gold.csv')}
config_ids = {p.stem for p in (bench / 'evaluation/configs').glob('task_*.json')}
assert set(ids) == gold_ids == config_ids, '清单、gold 与配置题号不一致'
for task in ids:
    source = bench / 'input' / task
    assert (source / 'task.json').is_file(), source
    assert (source / 'context').is_dir(), source

dest = root / 'input60'
assert not dest.exists(), 'input60 已存在：先检查已有数据，不自动覆盖'
dest.mkdir()
for task in ids:
    source = bench / 'input' / task
    target = dest / task
    target.mkdir()
    shutil.copy2(source / 'task.json', target / 'task.json')
    shutil.copytree(source / 'context', target / 'context')
assert not list(dest.rglob('gold.csv')), '解题输入中意外出现 gold.csv'
print(f'准备完成：{len(ids)} 题，输入目录 {dest}')
print('第一道公开题：', ids[0])
PY
```

不要写成 `task_1` 到 `task_60`。当前清单第一题为 `task_10`，60 题分散在完整 410 题编号中。

Agent 只接收 `input60`，不要提供完整 benchmark 根目录，也不要把评分结果或 gold 加进提示词。仅分目录并不构成操作系统级隔离；若启用可执行任意代码的工具，还需检查工具可读路径和日志，确认解题过程没有访问答案目录。

## 5. 配置校内模型并检查工具调用

### 5.1 申请令牌

登录 ChatECNU，通过头像菜单的“我的令牌”取得 API Key，具体权限和配额以校内平台为准。官方文档确认采用 Bearer 鉴权，API 基础地址为：

```text
https://chat.ecnu.edu.cn/open/api/v1
```

在 Ubuntu 的同一个终端、`champion` 仓库目录中设置：

```bash
export MODEL_API_URL='https://chat.ecnu.edu.cn/open/api/v1'
export MODEL_NAME='ecnu-plus'
read -r -s -p '输入 ChatECNU API Key: ' MODEL_API_KEY
printf '\n'
export MODEL_API_KEY
unset MODEL_API_URLS DEFAULT_MODEL_API_URLS
export ASR_BACKEND='local'
```

`ecnu-plus` 是起步示例，可换为账户支持的模型。这里直接配置源码实际使用的 `MODEL_*` 变量，避免既有变量覆盖 README 的 `DEFAULT_MODEL_*` 默认值。`read` 步骤由你在交互式 Ubuntu 终端输入密钥，命令本身不包含令牌。新开终端后需重新设置变量。

参考项目没有在上述启动入口自动加载 `.env` 的保证。如自行添加 `.env`，须明确加载方式，并只提交不含真实密钥的 `.env.example`。

### 5.2 小请求连通性与 function calling 检查

此步骤会调用模型并消耗少量额度。基础地址不要填写完整的 `/chat/completions` 路径。

```bash
uv run --frozen python - <<'PY'
import json
import os
import urllib.request

tool = {
    'type': 'function',
    'function': {
        'name': 'echo',
        'description': '返回提供的文本',
        'parameters': {
            'type': 'object',
            'properties': {'text': {'type': 'string'}},
            'required': ['text']
        }
    }
}
body = {
    'model': os.environ['MODEL_NAME'],
    'messages': [{'role': 'user', 'content': '请调用 echo 工具，参数 text 为 OK。'}],
    'tools': [tool],
    'stream': False
}
request = urllib.request.Request(
    os.environ['MODEL_API_URL'].rstrip('/') + '/chat/completions',
    data=json.dumps(body).encode('utf-8'),
    headers={
        'Authorization': 'Bearer ' + os.environ['MODEL_API_KEY'],
        'Content-Type': 'application/json'
    },
    method='POST'
)
with urllib.request.urlopen(request, timeout=60) as response:
    result = json.load(response)
message = result['choices'][0]['message']
print(json.dumps(message, ensure_ascii=False, indent=2))
calls = message.get('tool_calls') or []
assert any(c.get('function', {}).get('name') == 'echo' for c in calls), \
    '请求已返回，但未观察到预期工具调用，需要进一步检查模型与接口兼容性'
print('模型接口返回了工具调用；继续做 Agent 单题测试。')
PY
```

这只验证接口返回工具请求，不代表完整 Agent 循环通过。实际单题还要验证工具结果回传、多轮推理和 CSV 生成；视频任务还需验证多模态图像输入。

## 7. 单题试跑，再运行完整 60 题

### 7.1 每次实验创建独立目录

保持前面的模型环境变量已设置。以下命令仍在 Ubuntu 中：

```bash
cd "$HOME/kdd2026/champion"
export KDD_ROOT="$HOME/kdd2026"
export RUN_ID="baseline_$(date +%Y%m%d_%H%M%S)"
export RUN_DIR="$KDD_ROOT/runs/$RUN_ID"
export INPUT_DIR="$KDD_ROOT/data/input60"
export OUTPUT_DIR="$RUN_DIR/predictions"
export TEMP_DIR="$RUN_DIR/temp"
mkdir -p "$OUTPUT_DIR" "$TEMP_DIR"

{
  date -Is
  git rev-parse HEAD
  uv --version
  uv run --frozen python --version
  sha256sum uv.lock
  printf 'MODEL_NAME=%s\nMODEL_API_URL=%s\nINPUT_DIR=%s\n' \
    "$MODEL_NAME" "$MODEL_API_URL" "$INPUT_DIR"
} > "$RUN_DIR/versions.txt"
```

不要把 API Key 写入版本记录。工作目录始终保持 `champion`，避免相对路径导入和工具执行失效。

### 7.2 试跑一道真实公开题

```bash
set -o pipefail

  --only-tasks task_10 \

```

30 分钟是本指南设置的外层调试限时，不是官方限时。超时返回码通常为 124，需记录为失败并检查日志。

### 7.3 单题通过后运行 60 题

重新执行 7.1 创建一个新实验目录，再执行：

```bash
set -o pipefail
timeout 8h uv run --frozen python src/data_agent_baseline/zz_agent_v2.py \
  --max-parallel 1 \
  2>&1 | tee "$RUN_DIR/console.log"
```

因为 `INPUT_DIR` 已物理限制为 60 题，这里不会误跑其他 350 题。8 小时也是可调整的本地预算，不代表预计耗时。先在并发 1 下稳定运行，评估 API 限流、内存和视频耗时，再考虑提高至 2 或 4。参考代码本地默认任务并发为 16，本指南显式覆盖该值。

运行完检查预期文件：

```bash
uv run --frozen python - <<'PY'
import json
```

## 8. 课程评分与官方补充评测

### 8.1 两套评分不能混淆

| 评分方式 | 当前行为 | 使用场景 |
| --- | --- | --- |
| 课件链接的 `run_compare_to_gt.py` | 按归一化后的列内容匹配，允许部分分，惩罚额外列，λ＝0.1 | 与 75.6387 课程基线比较 |
| DataSpace 官方 `evaluation/evaluate.py` | 配置驱动的整表正确性，逐题二元评分，保留行内关联及需要的行序 | 可作为补充严谨性检查，单独报告 |

课件将 `evaluation/configs/` 作为数据资料的一部分。但当前课程列匹配脚本并不读取该配置目录，不能宣称它执行了所有配置中的精度或行序要求。

课程评分器对每列独立生成内容签名，因此可能忽略跨列的行对应关系。例如两列各自的值完全一致，但“地区”和“销售额”的配对发生错位，列评分仍可能很高。应检查业务正确性，补充官方整表评测，不能只追逐列分数。

### 8.2 运行课程指定评分器

预测运行完成后，在同一个终端执行：

```bash
cd "$HOME/kdd2026/champion"
uv run --frozen python src/data_agent_baseline/run_compare_to_gt.py \
  "$OUTPUT_DIR" \
  --gold-path "$HOME/kdd2026/data/DataSpace-Benchmark/output" \
  2>&1 | tee "$RUN_DIR/evaluation.log"
```

当前脚本 `LAMBDA_EXTRA = 0.1`，没有 `--lambda` 命令行参数。显式传预测与 gold 路径，避免使用作者机器上的默认路径。评测应遍历完整 60 个 gold，生成预测目录中的 `scores.csv`、`scores_summary.json` 等记录。

计算关系：

```text
单题分数 = max(0, 匹配列数 / Gold列数 − 0.1 × 额外列数 / 预测列数)
课程百分制得分 = 60题单题分数平均值 × 100
```

缺失预测记 0；零列等边界情况由脚本处理。不要把脚本给出的 0–1 均值直接与 75.6387 比较，也不要使用“仅已生成预测题”的均值作为总成绩。

```bash
uv run --frozen python - <<'PY'
import json
import os
from pathlib import Path
import pandas as pd

out = Path(os.environ['OUTPUT_DIR'])
scores = pd.read_csv(out / 'scores.csv')
expected = set(json.loads(
    (Path.home() / 'kdd2026/data/public_reference_tasks.json').read_text()
)['task_ids'])
assert len(scores) == 60 and set(scores['task_id']) == expected
s = scores['score']
assert s.notna().all() and s.between(0, 1).all()
full = s.ge(1 - 1e-12)
zero = s.le(1e-12)
print(f'课程得分：{s.mean() * 100:.4f} / 100')
print('满分 / 部分分 / 零分：', int(full.sum()), int((~full & ~zero).sum()), int(zero.sum()))
print(f'与课程参考基线差值：{s.mean() * 100 - 75.6387:+.4f}')
PY
```

任务耗时、token 和失败原因还应从 `$TEMP_DIR/logs/`、`token_summary.json`、`timing_summary.json` 及控制台日志汇总。评分脚本对日志位置有自己的假设，当预测与 temp 分目录时，不能假定 `scores.csv` 会自动带齐耗时信息。

## 9. 常见问题定位

| 现象 | 先检查什么 | 操作方向 |
| --- | --- | --- |
| PowerShell 不认识 `export`、`bash` 或路径不对 | 是否把 Bash 命令粘贴进 Windows 终端 | 打开 Ubuntu 终端，使用 Linux 路径 |
| 缺少 Python 包 / 找不到 `agents_v2` | Python 环境、仓库工作目录、启动文件 | 进入 `champion`，用本文 `uv run --frozen python ...` 命令 |
| uv 下载或解析失败 | `uv.toml` 包源、网络、Python 版本、锁定包可用性 | 保留错误日志，先处理源与环境，避免直接全面升级 |
| 401 / 403 | 令牌、账户权限、服务访问范围 | 重新核对平台令牌与权限，不把密钥写进日志 |
| 404 / 模型不存在 | API 基础地址、模型名 | 基础地址以 `/v1` 结束，核对账户支持的模型 |
| 429 / 批量大量失败 | 配额、并发和内部子调用 | 并发降到 1，按服务规则退避，记录失败原因 |
| 能聊天但工具调用失败 | `tool_calls`、工具 schema、工具回传消息兼容性 | 先通过 5.2，再验证完整单题循环 |
| ASR 提示缺少缓存 | 尚未下载 tiny/medium | 先下载再运行 `prepare_models.sh` |
| 下载过模型仍找不到 | `champion/asr_models/<name>` 是否有真实文件 | 检查四个必需文件及仓库相对路径 |
| 系统 FFmpeg 可用但视频任务失败 | `static-ffmpeg` 与 PyAV 预检 | 运行第 6 节预检并查看具体失败项 |
| 全部评分为 0 | 输出目录层级和文件名 | 确认根目录下直接是 `task_N/prediction.csv` |
| 列评分高但结果看起来不对 | 跨列配对、单位、去重、时间口径、排序 | 检查工具计算证据并运行整表评测 |
| 运行没有结束或预算超出 | 工具死循环、模型请求耗时、ASR、重试 | 查看每题日志，增加明确轮数/超时控制并记录修改 |

## 10. 开发、优化与提交安排

建议按以下验收关口推进，每次改动保存独立实验编号：

1. 环境验收：依赖导入、API 工具调用、多媒体预检通过。
2. 单题验收：真实题目能完成工具循环并输出 CSV，日志可追溯。
3. 批量验收：固定 60 题全部被调度，成功或失败均有记录。
4. 基线验收：统一评分器、固定 λ＝0.1、分母 60，保存初始成绩。
5. 改进验收：围绕文件发现、业务规则读取、SQL/表格工具、文档/视频抽取、错误恢复、输出校验逐项改进；对照实验尽量只改变一个因素。
6. 报告验收：解释成功和失败案例、优化效果、运行成本及个人贡献。

60 题有公开答案，可用于运行后的分析，但不能让答案进入求解过程。反复根据这 60 题调优会产生对公开集的适配，报告应如实说明，不能把公开集成绩直接等同于未知任务泛化能力。

课程必交六项：

- 完整项目源码：通用 Agent、工具、批量执行和错误恢复。
- 环境与依赖配置：锁文件、Python 版本、模型配置、无真实密钥的模板。
- 预测结果 CSV：按题保存，失败原因单独记录。
- 复现文档：数据准备、安装、配置、运行和评测命令。
- 实验评测记录：60 题逐题分数、均分、耗时、日志、基线对比。
- 详细期末报告：设计、实现、优化、实验与分析。

使用参考仓库或 AI 工具时，报告说明引用版本、使用方式、修改内容和个人实现。不要将参考冠军方案的原始成绩当成自己的成绩；同样，换用模型后也不能假定自动复现课件的 75.6387 分。
